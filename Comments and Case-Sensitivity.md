## Comments and Case-Sensitivity in Different Technolgy Stacks

| Category        | Language / Tech                                                     | Comment Syntax                                                           | Case-Sensitivity                                                                                                                                                                                                                                                                                  | Notes / Exceptions                                                                                             |
| --------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| **Programming** | C++ / Java                                                          | Single: `// text` <br> Multi: `/* text */`                               | **C++:** Sensitive (keywords lowercase, variables/functions case-sensitive) <br> **Java:** Sensitive (keywords lowercase, ClassNames PascalCase)                                                                                                                                                  | Java class name must match file name; <br> C++ allows flexible file/class naming                               |
|                 | Python & frameworks <br> (Python, Django, Flask)                    | Single: `# text` <br> Multi: `""" text """`                              | **Python:** Sensitive (`var` ≠ `Var`; special constants like `True`, `False`, `None`) <br> **Django + Flask:** Inherits Python rules; variables, functions, class names case-sensitive                                                                                                            | None specific; Django/Flask inherit Python rules                                                               |
| **Front-End**   | HTML                                                                | `<!-- text -->`                                                          | **HTML:** Case-Insensitive _(XHTML is case-sensitive)_                                                                                                                                                                                                                                            | XHTML requires lowercase tags and attributes                                                                   |
|                 | Handlebars (hbs)                                                    | `{{!-- comment --}}`                                                     | **Handlebars:** Case-Insensitive (follows HTML behavior)                                                                                                                                                                                                                                          | None                                                                                                           |
|                 | CSS family (CSS + SCSS)                                             | CSS: `/* text */` <br> SCSS: `// text` (not in output) <br> `/* text */` | **CSS:** Properties insensitive, values sometimes sensitive (`red` vs `RED`) <br> **SCSS:** Same as CSS                                                                                                                                                                                           | SCSS `//` comments not included in compiled CSS                                                                |
|                 | JavaScript + Modern React stack (JS + React + Next.js + TypeScript) | JS/TS: `//`, `/* */` <br> JSX: `{/* text */}`                            | **JavaScript:** Sensitive (variables/functions case-sensitive) <br> **React:** Sensitive (Components PascalCase, HTML tags lowercase, variables case-sensitive) <br> **Next.js + TypeScript:** Sensitive (type/interface names PascalCase, variables camelCase; file/folder names case-sensitive) | Next.js file/folder names are case-sensitive on most OS; <br> TypeScript adds stricter type/interface rules    |
| **Backend**     | JavaScript backend <br> (Node.js + Express.js)                      | Single: `// text` <br> Multi: `/* text */`                               | **Node.js:** Sensitive (inherits JavaScript; variables, functions, file names case-sensitive) <br> **Express.js:** Sensitive (routes can be case-sensitive depending on config)                                                                                                                   | Express route sensitivity may vary based on OS or web server config                                            |
| **Database**    | SQL <br> (MySQL + PostgreSQL / PL-SQL)                              | Single: `-- text` <br> Multi: `/* text */`                               | **SQL / PL-SQL:** Case-Insensitive (keywords usually uppercase) <br> **MySQL:** Mostly case-insensitive on Windows, case-sensitive on Linux (table/column names) <br> **PostgreSQL:** Case-insensitive for keywords, case-sensitive for identifiers unless quoted                                 | MySQL sensitivity depends on OS and storage engine; <br> PostgreSQL requires quotes for mixed-case identifiers |
|                 | MongoDB                                                             | `// text` (shell) <br> `/* text */`                                      | **MongoDB:** Sensitive (collection & field names case-sensitive; queries case-sensitive unless using collation)                                                                                                                                                                                   | None; collation can alter query sensitivity                                                                    |

### Quick Notes (to remember easily)

- Most programming languages & thier frameworks (C++, Java, Python, Django, Flask) → ✅ Case-sensitive
- JavaScript ecosystem (JavaScript, TypeScript, React, Next.js, Node.js, Express) → ✅ Fully case-sensitive
- HTML & template markup (HTML, Handlebars) → ❌ Case-Insensitive
- CSS / SCSS → ⚠️ Mixed behavior
- SQL databases (MySQL, PostgreSQL, PL/SQL) → ❌ Mostly case-Insensitive (DB/OS dependent)
- MongoDB (NoSQL) → ✅ Case-sensitive by default

### Exceptions :

1. CSS selectors are generally case-insensitive, this includes class and ID selectors. So, CSS properties, values, pseudo class names, pseudo element names, element names are case INsensitive.
    - But HTML class names are case-sensitive. And CSS class, id , urls, font-families are case sensitive

2. By convention, Java programs are written entirely in lower-case characters with three exceptions :
    - The first letter of class names are capitalized to distinguish class names from member names.
    - The names of constant fields are written entirely capital letters. e.g., the built-in Java class Integer includes the constant static fields MIN_VALUE and MAX_VALUE.
    - The first letter in each word in a compound identifier after the first are capitalized. e.g., the built-in Java class Object includes a method called toString(). The capital S signifies the beginning of a word within the compound name toString().
